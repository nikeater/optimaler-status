{# One editable field, for the two forms that have them. Extracted in part 19, when the counterparty page became the second surface that renders a `FieldView`. The alternative was thirty lines of markup in two files, and the second copy is the one that stops being edited: the first thing it would have lost is the whitespace discipline below, which this project has already shipped as a bug once. EVERY CONDITIONAL ATTRIBUTE CARRIES ITS OWN LEADING SPACE, and that is that bug. The environment runs with `trim_blocks` and `lstrip_blocks` (api/metrics.py), so the newline after an `{% endif %}` and the indent before the next `{% if %}` are both removed - two conditional attributes on consecutive lines therefore render as one attribute with both names glued together (`requiredaria-describedby`), and the browser quietly has neither. A leading space inside each condition is the only form that cannot be undone by whitespace control. `first` is the row's business rather than the field's: the "wird versiegelt" tag is shown once per row and not once per input, because four identical tags next to four address boxes teach nothing and crowd the label they belong to. IMPORTED `with context` wherever it is used, and that is load-bearing. `t` is installed as an environment global in ONE language (`api/metrics.py::_install` puts German there) and handed to each render as context in the reader's. A macro imported without context would see the global - so an English page would come back with German labels on every field. #} {% macro editable(field, first=True) %}
